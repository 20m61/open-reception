## 2. このセッションで確定した事実（再調査不要）

### 体験設計の差分は A / B が決着した

`docs/experience/state-mapping.md` §5 のうち **A（名前が違うだけ）と B（状態が無く観測できない）
は決着済み**。B は 6 項目あったが、**体験状態を 1 つも増やさずに済んだ**:

- 3 つ（`visitor_detected` / `recognizing` / `choosing_method`）は**元から実装済み**だった
- 2 つ（`no_match` / `network_degraded`）は状態以外の手段で解決（計測配線・文言分岐）
- 1 つ（`privacy_blocked`）は **README に定義文が無く判断できない**（判断待ち）

残るのは C（音声とタッチの `confirming` 統合）と D（QR 受付の統合）で、どちらも要ユーザー確認。

### 実装の状態語彙は 6 つある（3 ではない）

`ReceptionState` / `KioskMode` / `VoiceKioskMode` / `voiceListeningStage` / `PresenceState` /
`CheckinState`。第 34 wave が 3 と数えたせいで派生した判定がまとめて誤っていた。
**採録基準と除外理由は `src/domain/experience/journey-map.ts` に全件登録**してあり、
`src/domain/**` に新しい状態語彙が生まれて未登録ならテストが落ちる。

### 来訪者向けの翻訳漏れは 0 件

allowlist に残る 77 箇所は**恒久除外の 4 分類**（端末ゲート系 / ja 専用の既定値 /
訳は完備 / 画面に出ない）。分類の根拠は `handoff-2026-07-27.md` §0 の表。

> **判定は生 CJK の件数ではなく「その module が `locale` を受け取っているか」で行う。**
> 訳し終えた module にも ja の訳文は残るので、件数は指標にならない。

### `--full` ゲートはこの環境で通る

第 47 wave で 2 件の障害を除去した。lighthouse は `CHROME_PATH` をゲートが自動補完する
（`playwright.config.ts` と同じ理由・同じパス）。**「重いから後で」で飛ばさないこと** —
10 周回飛ばしている間に実際に赤くなっていた。

## 3. 引き継ぎ事項

### A. 「網羅」を手で列挙したリストで担保しない（3 回踏んだ）

第 44〜46 wave はいずれも同じ形だった。対象は違うが、**新しいものを足したときに気づけない**
点が同じ。

| 対象 | どう塞いだか |
| --- | --- |
| CJK allowlist | 例外なのに違反 0 のファイルを落とす（`src/lib/i18n/cjk-literal.test.ts`） |
| admin ナビ | ルートを走査し、ナビ登録か理由付き非掲載かを強制（`navigation.test.ts`） |
| 認可ガード | 全 admin/platform ルートがガードを参照しているか静的検証（`authz-coverage.test.ts`） |

**共通の対処**: 実体（ファイル・ルート・語彙）を走査し、「登録済み」か「**理由付き**の除外」かを
強制する。理由の長さも検査する（空文字や「同上」で誤魔化せなくする。実際に自分の手抜きが
1 件落ちた）。

### B. 独立レビューは「自分が今書いた結論」にこそ効く

このセッションで 3 回使い、**3 回とも結論か実装が変わった**。

- #454: 「`choosing_method` は状態化しない」と決着させかけたが、`CheckinState.selectingMethod`
  が実在すると指摘され撤回
- #455: 自分の変更には BLOCKER 無しとしつつ、**より重い既存欠陥（#456 の行き止まり）を発見**
- #459: 初版が #374 と重複した語彙を作っていた + mutation で「落ちないテスト」3 件を暴かれた

**分析の結論を含む変更は `change-reviewer-opus5` へ回すこと。**「その語を実際に grep して
確かめよ」と明示すると、憶測ではなく事実で返ってくる。

### C. 「無い」と書く前に、実際に開く

このセッションで**私の見立ての誤りが 4 件**あった。いずれも実コードを開けば分かるもの。

| 誤り | 実際 |
| --- | --- |
| 「`visitor_detected` / `recognizing` は状態語彙に無い」（第 34 wave） | `PresenceState` と `voiceListeningStage` に在った |
| 「読み上げ原稿 36 箇所が最大の翻訳漏れ」（第 40 wave） | `guidance.ts` は 5 ロケール × 全 9 状態を完備。漏れではない |
| 「`AiGuidancePanel` は来訪者向けの未対応」（第 40 wave） | **どこからも描画されていない**（#104 の未配線 increment） |
| 「`@lhci/cli` の js-yaml override が脆弱」（第 47 wave） | 脆弱なのは eslint 経由の 4.2.0。override は無関係 |

**grep するだけでは足りない。「その module が実際に描画・使用されているか」まで辿る。**

### D. brace-expansion は現状「直せない」

advisory の対象は `<=5.0.7` で、**2.x 系に修正版が存在しない**（最新 2.1.2 も対象内）。
唯一の修正版 5.0.8 へ override で寄せると、エクスポート形が変わっていて `minimatch`（CJS）が
`TypeError: expand is not a function` で落ち、**eslint が起動しなくなる**。

経路は `@opennextjs/aws` → `@node-minify/core` → `glob@9` → `minimatch@8` と
`typescript-eslint` で、いずれも **dev 依存**（ゲートの `--omit=dev` は 0 件）。

> **再挑戦するときは `npx eslint .` を回すこと。** `npm install` は成功し `npm audit` も 0 件に
> なるので、**インストールだけでは壊れたことに気づけない**。

### E. バージョン固定の override は、あとで脆弱性修正を塞ぐ

`postcss` の override が `>=8.5.10` で下限を固定しており、修正版 8.5.18+ の解決を塞いでいた
（＝脆弱性対応で足した override が、次の脆弱性修正を塞ぐ側に回っていた）。
**`npm audit` が override 済みパッケージを指したら、まず override 自体を疑う。**

### F. 常設される UI は画面分岐の外に置く

逃げ道バーは「待機以外の全画面に常設」される前提で設計され、その前提のもとで各画面から
後退ボタンを撤去してある。ところがバーが既定受付の枝の**中**に在ったため、カスタム受付
フローの 2 画面では逃げ道が 1 つも出ず、**60 秒の無操作リセットを待つしかない行き止まり**に
なっていた。**コメントが「常設」と書いていても、構造が保証していなければ嘘になる。**
