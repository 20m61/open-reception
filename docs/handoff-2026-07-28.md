## 3. 引き継ぎ事項

### A. 「網羅」を手で列挙したリストで担保しない（3 回踏んだ）

第 44〜46 wave はいずれも同じ形だった。対象は違うが、**新しいものを足したときに気づけない**
点が同じ。

| 対象 | どう塞いだか |
| --- | --- |
| CJK allowlist | 例外なのに違反 0 のファイルを落とす（`src/lib/i18n/cjk-literal.test.ts`） |
| admin ナビ | ルートを走査し、ナビ登録か理由付き非掲載かを強制（`navigation.test.ts`） |
| 認可ガード | 全 admin/platform ルートがガードを参照しているか静的検証（`authz-coverage.test.ts`） |

**共通の対処**: 実体（ファイル・ルート・語彙）を走査し、「登録済み」か「**理由付き**の除外」かを
強制する。理由の長さも検査する（空文字や「同上」で誤魔化せなくする。実際に自分の手抜きが
1 件落ちた）。

### B. 独立レビューは「自分が今書いた結論」にこそ効く

このセッションで 3 回使い、**3 回とも結論か実装が変わった**。

- #454: 「`choosing_method` は状態化しない」と決着させかけたが、`CheckinState.selectingMethod`
  が実在すると指摘され撤回
- #455: 自分の変更には BLOCKER 無しとしつつ、**より重い既存欠陥（#456 の行き止まり）を発見**
- #459: 初版が #374 と重複した語彙を作っていた + mutation で「落ちないテスト」3 件を暴かれた

- #469: ADR 0007 の結論が **2 箇所で誤り**と判明（「等価性は保証されている」は安全側と等価性の
  混同、「`REQUIRES_CONFIRMATION_ACTIONS` が音声を止める」は事実に反する）

**分析の結論を含む変更は `change-reviewer-opus5` へ回すこと。**「その語を実際に grep して
確かめよ」と明示すると、憶測ではなく事実で返ってくる。**4 回中 4 回とも結論が動いた**ので、
これは「念のため」ではなく**必須の手順**として扱うこと。

### D. brace-expansion は現状「直せない」

advisory の対象は `<=5.0.7` で、**2.x 系に修正版が存在しない**（最新 2.1.2 も対象内）。
唯一の修正版 5.0.8 へ override で寄せると、エクスポート形が変わっていて `minimatch`（CJS）が
`TypeError: expand is not a function` で落ち、**eslint が起動しなくなる**。

経路は `@opennextjs/aws` → `@node-minify/core` → `glob@9` → `minimatch@8` と
`typescript-eslint` で、いずれも **dev 依存**（ゲートの `--omit=dev` は 0 件）。

> **再挑戦するときは `npx eslint .` を回すこと。** `npm install` は成功し `npm audit` も 0 件に
> なるので、**インストールだけでは壊れたことに気づけない**。

### E. バージョン固定の override は、あとで脆弱性修正を塞ぐ

`postcss` の override が `>=8.5.10` で下限を固定しており、修正版 8.5.18+ の解決を塞いでいた
（＝脆弱性対応で足した override が、次の脆弱性修正を塞ぐ側に回っていた）。
**`npm audit` が override 済みパッケージを指したら、まず override 自体を疑う。**

### F. 「統合するか否か」は、並存のコストを実測してから決める

差分 D（QR 受付の統合）は、統合の是非を先に決めず**並存のコストを測った**。コストは
「**片方に入れた修正がもう片方へ伝播しないこと**」で、実害が 1 件出た（第 36 wave で通常受付に
入れた「通信断とサーバ失敗を分ける」修正が QR 側に無かった）。**測ってから決めると、
統合しない場合に何を払い続けるかも同時に分かる。**

なお伝播漏れの**機械検出は見送った**。2 つの状態機械は局面が違うので「同じ修正が両方に
在ること」を機械的に定義できない（受付側は `failureReason`、QR 側は HTTP ステータス由来で
形が違う）。**メタテストが有効な場面とそうでない場面がある。**

### G. 常設される UI は画面分岐の外に置く

逃げ道バーは「待機以外の全画面に常設」される前提で設計され、その前提のもとで各画面から
後退ボタンを撤去してある。ところがバーが既定受付の枝の**中**に在ったため、カスタム受付
フローの 2 画面では逃げ道が 1 つも出ず、**60 秒の無操作リセットを待つしかない行き止まり**に
なっていた。**コメントが「常設」と書いていても、構造が保証していなければ嘘になる。**

### 前セッションの「`--full` green」との食い違い（重要）

本書冒頭は「`--full` ゲート green（gitleaks / semgrep のみ未インストールで **SKIP**）」と
書いていた。**SKIP は green ではない。** 両ツールが入っている環境で実行したところ、
gitleaks 2 件・semgrep 3 件が実際に検出され、e2e も red だった。

`--strict` を付けると SKIP は FAIL になる。**未導入ツールがある環境の `--full` は
`--strict` 併用でないと「通った」と言えない**（`docs/quality-gate.md` の定期運用節が
`--strict` 必須としているのはこのため）。

### ゲートはフックで強制されるようになった

`scripts/hooks/pr-gate-guard.sh`（`.claude/settings.json` で登録・チーム共通）が
`gh pr create`（要 `--pr` 以上）/ `gh pr merge`（要 `--full`）を、現在の作業ツリーに対する
green 記録が無ければブロックする。記録はツリーの**内容**指紋に紐づくので、ゲート後に
編集すれば無効になり、コミットしただけでは無効にならない。

迂回は `OPEN_RECEPTION_SKIP_GATE_GUARD=1` を**コマンド行に直接書く**
（フックは実行前の別プロセスなので環境変数では届かない）。

### 引き継ぎ事項（再発しやすいもの）

- **`gitleaks detect` は作業ツリーではなく git 履歴を走査する。** 現行コードを直しても
  過去コミットの検出は消えない。`.gitleaksignore` に指紋（`commit:file:rule:line`）で
  narrow に受容する。**ignore ファイルに検出値そのものを書かないこと**（そのファイル自身が
  新たな検出源になる。実際に踏んだ）。
- **無操作オーバーレイによる e2e フレーク**: 警告までの猶予は `limit - warnMs`、
  `warnMs = min(INACTIVITY_WARNING_MS, limit - 500)`。展開すると **limit が 10.5s 未満なら
  猶予は常に 500ms 固定**。`?inactivityMs=` の値を大きくしても直らない。検証したい状態だけを
  `?inactivityMs.<state>=` で短縮する（`src/domain/kiosk/inactivity.ts`）。
- **`chromium-ipad` は `pristine-state` に `dependencies` で依存する。** pristine の VRT が
  落ちると 189 件中 178 件が実行すらされずスキップされる。**「落ちている」ように見えるものが
  未実行のことがある**。e2e の失敗は必ず実行件数と併せて読む（#477 はこれで誤診した）。
- **ローカル `main` を実質の main として扱わない。** `git fetch` せずに起票・調査すると、
  既に直っている問題を追いかける（#477 / #478 が実際にそうなり、2 件とも実装不要だった）。
- **VRT ベースラインの自動生成は退行を「正」として焼き付ける**（`playwright.config.ts` L93-98）。
  生成物は必ず既存プラットフォーム版と目視比較してから採用する。
- **コミットメッセージを heredoc で渡すと ssh 署名が失敗することがある**
  （`1Password: failed to fill whole buffer`）。stdin を heredoc が占有し、git が起動する
  署名ヘルパが commit オブジェクトを読めなくなるため。**メッセージはファイルに書いて
  `-F <path>` で渡す**。1Password のロックと紛らわしいので切り分けに注意。
