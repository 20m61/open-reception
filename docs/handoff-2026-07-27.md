## 2. このセッションで確定した事実（再調査不要）

### ブラウザ e2e はこのコンテナで動く

**第 15 wave の申し送り「exit 144 でブロックされ実行不可」は誤りだった。** 真因は Playwright
1.61.1 が要求する chromium ビルド（1228）とプリインストール版（1194）の不一致で、
`executablePath` を渡せば動く。`playwright.config.ts` が `/opt/pw-browsers/chromium` を
自動検出するようにしたので、**追加の env 指定なしで `--e2e` が通る**。

この stale な記録が 5 周にわたって「UI 変更はブラウザ検証できない」という誤った前提を作り、
#422 の着手判断を歪めていた。**環境の制約を記録するときは、次の周回が再検証できる形
（再現コマンドと実際の失敗メッセージ）で残すこと。**

### e2e の project 構成は 3 段（前後で共有状態を挟む）

```
pristine-state（既定シード前提）→ chromium-ipad（本体）→ flow-mutation（破壊的）
```

- `pristine-state` = `kiosk-checkout-i18n` / `kiosk-vrt-a11y`。**在館者ゼロ・seed の担当者のみ**を
  前提にしており、他 spec が残した来訪者・担当者があると空状態の文言と画面の高さが変わって落ちる。
- `flow-mutation` = 既存（#248/#321）。フローや共有シングルトン設定を書き換える spec。

### VRT baseline の落とし穴（実際に踏んだ）

スナップショット名は既定で **project 名を含む**。project を分けただけで別名になり、
**レビュー済み baseline が孤立して、その場の描画が新 baseline として自動生成される**
（＝退行がそのまま「正」として焼き付く）。`snapshotPathTemplate` で `chromium-ipad` 名に
固定して回避した。**VRT を別 project へ移すときは baseline の解決先を必ず確認すること。**

### 端末一覧はページネーションされる

`/admin/devices` の行を e2e で掴むときは、**一意名で `device-filter-keyword` を絞ってから**。
フルスイートでは他 spec の作った端末に押し出されて 2 ページ目以降へ移る。

### 指紋が 2 種類ある（取り違え注意）

| 関数 | 含むもの | 用途 |
| --- | --- | --- |
| `computeConfigHash` | context（端末 ID）+ version + 内容 | `/api/configuration/effective` 応答の `configHash` |
| `computeSectionsHash` | **内容のみ** | 版のスナップショット指紋・版比較・端末が heartbeat で報告する値 |

端末ごとに変わる前者を「期待値」に使えないため、反映状況の突き合わせは後者で行う。

  retry で green、単独では 3/3 green）。しきい値を短く上書きして段階遷移を測る spec なので
  負荷に弱い。**分割・リファクタの退行と取り違えないこと**（疑ったら単独で複数回回す）。
- **移行フラグの既定は OFF**。`/kiosk?effectiveConfig=1` で新経路、`=0` で旧経路（ADR 0004）。


- **UI / a11y に触る変更は `./scripts/quality-gate.sh --pr --e2e` を通してから PR を出す。**
  e2e が動くようになったので、これを既定にできる。
- gitleaks は未導入（`--secrets` は SKIP）。テストの擬似値は `TEST-` 接頭辞を維持する。
- マージは squash + 直列。ゲート green + レビュー blocking なしなら自動マージ（CLAUDE.md 手順 8）。
- **本セッションで踏んだ手順ミス**: 一度、feature ブランチへ切り替えずに `main` へコミットした
  （push 前に気づいて移送）。wave の頭でブランチを確認すること。
- squash マージ後、remote の feature ブランチは削除されず残る（git プロキシが delete を拒否）。
  次 wave は `git reset --hard origin/main` してから `--force-with-lease` で上書きする運用でよい
  （旧 tip の内容は squash 済みで main と content-identical であることを確認してから）。
